================================================================================
PREGUNTAS PROBABLES EN LA REUNION - RESPUESTAS
================================================================================

1. ¿QUE ES ANGULAR STANDALONE?
   "Es la forma más moderna de Angular. Cada pantalla funciona independientemente,
   sin necesidad de módulos. Es más simple y más rápido de desarrollar."

2. ¿YA TIENES LISTAS LAS PANTALLAS?
   "Sí. Tengo 3 módulos (NIX, Cartelera, Contactos) con 3 pantallas cada uno.
   Total: 9 pantallas completas.
   Cada módulo tiene: Dashboard, Lista, Formulario (crear/editar)."

3. ¿COMO CONECTA EL FRONTEND CON EL BACKEND?
   "A través de APIs REST en HTTP. Frontend envía peticiones con datos en JSON.
   Backend responde con JSON. Ambos se entienden por ese formato."

4. ¿QUE ENDPOINTS NECESITA EL BACKEND?
   "5 endpoints por módulo:

   NIX:
   - GET /api/nix (traer lista)
   - GET /api/nix/:id (traer un registro)
   - POST /api/nix (crear)
   - PUT /api/nix/:id (editar)
   - DELETE /api/nix/:id (eliminar)

   CARTELERA:
   - GET /api/cartelera-standby
   - GET /api/cartelera-standby/:id
   - POST /api/cartelera-standby
   - PUT /api/cartelera-standby/:id
   - DELETE /api/cartelera-standby/:id

   CONTACTOS:
   - GET /api/contactos
   - GET /api/contactos/:id
   - POST /api/contactos
   - PUT /api/contactos/:id
   - DELETE /api/contactos/:id

   Total: 15 endpoints (5 por módulo)"

5. ¿COMO PREPARA ANGULAR LOS DATOS?
   "Usuario hace clic en Guardar
   → Angular recoge los valores del formulario
   → Los organiza en formato JSON
   → Los envía al Backend
   → Espera respuesta
   → Si es éxito: muestra mensaje positivo
   → Si es error: muestra mensaje de error"

6. ¿QUE PASA SI FALLA LA CONEXION?
   "Angular muestra un mensaje de error al usuario.
   Ej: 'No se pudo conectar, intenta de nuevo'
   Los datos del formulario no se pierden."

7. ¿CUAL ES EL PROTOCOLO DE COMUNICACION?
   "HTTP/HTTPS (estándar de internet)
   - GET: solicitar datos
   - POST: enviar datos nuevos
   - PUT: actualizar datos
   - DELETE: eliminar datos"

8. ¿QUE VALIDACIONES HACE EL FRONTEND?
   "Antes de enviar datos al Backend:
   - Verifica que campos obligatorios estén completos
   - Valida formatos (email, teléfono, etc.)
   - Muestra errores en rojo
   - Impide enviar si hay errores"

9. ¿COMO SE MANEJAN LOS DATOS DESPUES DE RECIBIR DEL BACKEND?
   "Angular recibe datos en JSON, los procesa y actualiza las pantallas.
   Si es una lista: actualiza la tabla
   Si es un formulario: rellena los campos
   Si es una eliminación: quita el registro de la lista"

10. ¿ES SEGURO ENVIAR DATOS POR HTTP?
    "Por ahora es desarrollo local (localhost). Para producción usaremos
    HTTPS (seguro) y autenticación (tokens, credenciales)."

11. ¿QUE PASA CON LOS DATOS ACTUALES EN RDS?
    "Opciones a decidir:
    - Opción A: Traer todos los datos de los 3 RDS a una BD central
    - Opción B: Backend consulta los 3 RDS simultáneamente
    - Opción C: Fase 1 con datos de prueba, Fase 2 con datos reales"

12. ¿QUE FRAMEWORK USASTE?
    "Angular 18 (última versión) con TypeScript.
    Estándar de la industria para aplicaciones empresariales grandes.
    Tiene tipado fuerte, componentes reutilizables, rendimiento optimizado."

13. ¿CUANTO TIEMPO TARDO EL FRONTEND?
    "La estructura base, rutas, validaciones y formularios están listos.
    Solo falta conectar con el Backend real.
    Una vez Backend tenga endpoints funcionando: 1-2 días de integración."

14. ¿SE PUEDE HACER RESPONSIVE (MOVIL)?
    "Sí. El Frontend ya está hecho responsive.
    Funciona en desktop, tablet y celular."

15. ¿COMO SE ACTUALIZA SI HAY CAMBIOS?
    "En desarrollo: servidor en hot-reload, cambio código y se actualiza solo.
    En producción: se recompila y se despliega."
